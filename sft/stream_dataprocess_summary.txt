● 简要结论
  使用方式: DataProcessor（普通 process_dataset）
  是否会走缓存: ✔️ 依据 enable_cache 创建/读取 Arrow 缓存文件
  是否会并行（多进程）: ✔️ num_proc 传给 Dataset.map 实现多进程并行
  ────────────────────────────────────────
  使用方式: StreamingDataProcessor（create_streaming_dataset）
  是否会走缓存: ❌ 不使用 DataProcessor 的缓存机制（因为数据是逐行读取的）
  是否会并行（多进程）: ❌ 多进程并行
    基本不可用，生成器本身是顺序的，Dataset.from_generator
    只能在单线程下消费
  ---
  1️⃣ 为什么 StreamingDataProcessor 不走缓存？

  - StreamingDataProcessor 只实现了两个额外方法：
  方法: create_streaming_dataset(self, file_path)
  作用: 读取文件行‑by‑line、把 JSON 行放进一个 Python list
    缓冲区（buffer_size），当缓存满了就 yield 出去，形成 流式
    datasets.Dataset。
  ────────────────────────────────────────
  方法: should_use_streaming(self, file_path, threshold=1 GB)
  作用: 根据文件大小决定是否走流式路径。
  - 这段代码 没有 调用 self.get_cache_path()、self.enable_cache 或 self.process_dataset 中的缓存写入逻辑。
  - 目的是 避免一次性把完整数据加载进内存，所以每次遍历都重新读取磁盘，缓存对它没有意义。

  ---
  2️⃣ 为什么流式处理几乎没有并行？

  - create_streaming_dataset 通过 普通 Python for 循环 把文件行读进 buffer，随后 yield from buffer 把它们一次性输出给 datasets.from_generator。
  - datasets.from_generator 本身是 单线程 的迭代器——它会在主进程中拉取每个 yield，并把数据喂给后面的 map/batch 操作。
  - Dataset.map 能接受 num_proc 参数实现多进程，但 流式数据（generator）在 map 前已经被“拉平”，此时已经失去了原始文件的随机访问能力，map 只能在单进程中运行（内部会报 TypeError: map() cannot be used with a generator）。

  换句话说：流式模式的 瓶颈 在于磁盘 I/O 和生成器的顺序读取，CPU 并行化的收益非常有限。

  ---
  3️⃣ 何时该选用哪一种？
  场景: 数据量 ≤ 数 GB，能一次性装入内存 需要多次实验、经常重复同一份数据
  推荐实现: DataProcessor + 缓存 （首次处理会生成 .arrow 缓存，后续直接读取，配合
    num_proc 获得 3‑5× 加速）
  ────────────────────────────────────────
  场景: 单个文件非常大（> 1 GB）或整体数据集远大于可用内存 一次性加载会 OOM
  推荐实现: StreamingDataProcessor
    （只在磁盘上顺序遍历，极低内存占用，适合一次性训练）
  ────────────────────────────────────────
  场景: 想要在超大数据上仍保持一定并行
  推荐实现: 仍然使用 DataProcessor，但把 分块（batch_size、num_proc）调大，并配合
    torch.utils.data.DataLoader 的
    num_workers；或者手动将大文件拆分成若干子文件再并行处理。

  ---
  5️⃣ 小建议与调优技巧

  1. 先检测文件大小 → should_use_streaming 自动判断是否需要流式。你可以在配置里加入 threshold_mb 参数来自定义阈值。
  2. 在流式模式下，如果机器有多块 SSD，考虑把原始大文件拆分为若干子文件，然后并行启动多个 StreamingDataProcessor（每个子文件单独进程）来间接实现并行。

  4. 内存监控：在流式模式下运行时，观察 psutil/torch.cuda.memory_allocated()，确认内存使用始终在可接受范围内。

  是否并行: ❌（单进程）
  ────────────────────────────────────────
  步骤: processor.process_dataset(raw_ds, ...)

  是否走缓存: ❌（缓存被禁用/失效）
  是否并行: ❌（num_proc 被强制为 1）
  所以在 流式处理大数据集 时，DataProcessor 能帮助完成 *文本格式化、tokenization、标签构建等业务逻辑*，但 并行和缓存 只能依赖 单进程顺序执行。

  4️⃣ 常用的变通方案
  场景: 需要低内存 + 一次性处理
  方案: 直接使用 StreamingDataProcessor → processor.process_dataset（不缓存）
  说明: 适合超大文件（> 几 GB）或机器内存受限的情况。
  ────────────────────────────────────────
  场景: 希望仍能利用缓存
  方案: 先把大文件 拆分 为若干子文件（如每 500 k‑1 M
    行一个），对每个子文件使用普通的 load_sft_dataset +
    DataProcessor（开启缓存、并行），最后用 datasets.concatenate 合并得到完整的
     Dataset。
  说明: 这样既保持了 低内存（每次只加载一个子块），又能享受 缓存 + 多进程 的加速。
  ────────────────────────────────────────
  场景: 想要并行但不想写缓存
  方案: 将流式数据 批量读取进内存块（如一次读取 batch_size 条记录），在块内部使用
    DataProcessor 的 preprocess_batch（内部已并行
    tokenization），处理完后立即写入磁盘或喂给 Trainer。
  说明: 需要自行管理块循环，缓存仍可关闭。
  ────────────────────────────────────────
  场景: 仅需一次性跑完整训练
  方案: 在训练脚本中检测文件大小
    should_use_streaming，若超过阈值则走流式（不缓存），否则走普通路径（缓存+并行）。
  说明: 这是我们在 training/sft.py 中已经实现的“自动切换”逻辑。

  from data.loaders import load_sft_dataset

      tokenizer=tokenizer,

  )

          tokenizer=tokenizer,
          template=template,

          batch_size=1000,
          enable_validation=True,
      )
      processed_ds = processor.process_dataset(raw_ds,
                                              desc="Streaming processing")
  else:

      raw_ds = load_sft_dataset(train_file, "prompt", "completion")

          batch_size=1000,
          enable_validation=True,
      )
      processed_ds = processor.process_dataset(raw_ds,
                                              desc="Normal processing")

  小结

  - 流式 → 只读、单进程、无缓存，适合极大文件或内存受限的场景。
  - 普通 DataProcessor → 支持缓存 + 多进程，适合中等规模或需要反复实验的情况。
  - 若想兼顾两者，可 将大文件切块或 分片并行后再合并，从而在保持低内存的同时仍享受缓存和并行的加速。

  """
  示例：拆分大型 JSONL、逐块缓存并行处理、合并为完整 Dataset
  """

  import os
  from pathlib import Path
  from typing import List

  from datasets import Dataset, concatenate_datasets
  from transformers import AutoTokenizer

  from data.loaders import load_sft_dataset
  from data.processors import DataProcessor

  # ----------------------------------------------------------------------
  # 1️⃣ 读取配置（可直接从 sft.yaml 读取，这里写死演示）
  # ----------------------------------------------------------------------
  TOKENIZER_NAME = "gpt2"
  CACHE_DIR = "data/cache"
  NUM_PROC = "auto"          # 自动检测 CPU 核数
  BATCH_SIZE = 1000
  ENABLE_CACHE = True
  ENABLE_VALIDATION = True

  # ----------------------------------------------------------------------
  # 2️⃣ 工具函数：把大文件按行数切分（一次性运行即可）
  # ----------------------------------------------------------------------
  def split_jsonl(in_path: str, out_dir: str, lines_per_file: int = 500_000) -> List[Path]:
      """将 JSONL 拆分为若干子文件，返回子文件路径列表"""
      os.makedirs(out_dir, exist_ok=True)
      parts = []
      buffer = []
      part_idx = 0

      with open(in_path, "r", encoding="utf-8") as src:
          for line in src:
              buffer.append(line)
              if len(buffer) >= lines_per_file:
                  part_path = Path(out_dir) / f"part_{part_idx:03d}.jsonl"
                  with open(part_path, "w", encoding="utf-8") as dst:
                      dst.writelines(buffer)
                  parts.append(part_path)
                  buffer.clear()
                  part_idx += 1

          # 写入剩余行
          if buffer:
              part_path = Path(out_dir) / f"part_{part_idx:03d}.jsonl"
              with open(part_path, "w", encoding="utf-8") as dst:
                  dst.writelines(buffer)
              parts.append(part_path)

      return parts

  # ----------------------------------------------------------------------
  # 3️⃣ 主流程：逐块处理并缓存
  # ----------------------------------------------------------------------
  def main():
      # ---- 参数 ---------------------------------------------------------
      large_file   = "data/large_train.jsonl"   # 你的大数据集路径
      split_dir    = "data/train_parts"        # 拆分后子文件目录
      template     = "### User:\\n{prompt}\\n\\n### Assistant:\\n"
      max_len      = 2048
      train_on_prompt = False
      add_eos_token   = True

      # ---- 1️⃣ 拆分（如果已经拆分可以跳过） -------------------------
      if not os.path.isdir(split_dir) or not any(Path(split_dir).glob("part_*.jsonl")):
          print(f"🔀 正在拆分 {large_file} → {split_dir}")
          parts = split_jsonl(large_file, split_dir, lines_per_file=500_000)
          print(f"✅ 完成拆分，共 {len(parts)} 个子文件")
      else:
          parts = sorted(Path(split_dir).glob("part_*.jsonl"))
          print(f"✅ 检测到已拆分的子文件，共 {len(parts)} 个")

      # ---- 2️⃣ 初始化 tokenizer -----------------------------------------
      tokenizer = AutoTokenizer.from_pretrained(TOKENIZER_NAME)
      if tokenizer.pad_token is None:
          tokenizer.pad_token = tokenizer.eos_token

      # ---- 3️⃣ 根据配置决定并行进程数 -------------------------------
      if NUM_PROC == "auto":
          num_proc = min(8, os.cpu_count() or 1)
      else:
          num_proc = int(NUM_PROC)

      # ---- 4️⃣ 创建 DataProcessor（缓存 + 并行已在参数中打开） -----
      processor = DataProcessor(
          tokenizer=tokenizer,
          template=template,
          max_length=max_len,
          train_on_prompt=train_on_prompt,
          add_eos_token=add_eos_token,
          enable_cache=ENABLE_CACHE,
          cache_dir=CACHE_DIR,
          num_proc=num_proc,
          batch_size=BATCH_SIZE,
          enable_validation=ENABLE_VALIDATION,
      )

      # ---- 5️⃣ 逐块加载、缓存、并行处理 -----------------------------
      processed_parts: List[Dataset] = []
      for part_path in parts:
          print(f"\n🚀 处理子文件: {part_path.name}")

          # 读取原始数据（不走缓存，仅负责把 JSONL 读取为 Dataset）
          raw_ds = load_sft_dataset(
              train_file=str(part_path),
              prompt_key="prompt",
              completion_key="completion",
          )

          # 这里会自动检测是否已有对应缓存文件；若有则直接加载，无需再次计算
          processed = processor.process_dataset(
              raw_ds,
              desc=f"Processing {part_path.name}",
          )
          processed_parts.append(processed)

      # ---- 6️⃣ 合并所有子数据集 ---------------------------------------
      print("\n🔗 合并子数据集 → 完整训练集")
      train_dataset = concatenate_datasets(processed_parts)
      print(f"✅ 合并完成，样本总数: {len(train_dataset)}")

      # 这里可以直接把结果保存为 Arrow（如果后续训练想直接读取）
      output_path = Path("data") / "train_processed.arrow"
      train_dataset.save_to_disk(str(output_path))
      print(f"💾 处理好的完整数据已写入: {output_path}")

  if __name__ == "__main__":
      main()

  4️⃣ 常见问题 & 小技巧

  1. 缓存失效
    - DataProcessor 的缓存键是基于 template、max_length、train_on_prompt、add_eos_token、tokenizer.name_or_path 生成的 MD5。只要这些值保持不变，load_from_disk 读取的文件就是最新的。如果您改动了任意一项（比如换了模型或修改了模板），请重新运行一次完整的预处理，以生成新的缓存文件。
  2. 多卡 / 分布式训练
    - load_from_disk 返回的 Dataset 已经是 完整的（不再依赖 map），可直接在多卡环境下使用 Trainer 的 accelerate 或 DeepSpeed 分布式策略，无需额外同步。
  3. 只想加载一部分
